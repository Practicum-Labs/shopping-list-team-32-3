# Авторизация — спецификация и принятые решения

> Документ описывает требования к экранам регистрации/входа/восстановления (ниже) и фиксирует
> командные решения по реализации. Декомпозиция задач — [auth-backlog.md](auth-backlog.md)
> (T-49…T-60). Макет экранов — [login-screen.html](login-screen.html) (открыть в браузере,
> 3 экрана × светлая/тёмная тема).

## Принятые решения

1. **Backend — реальный REST** (railway, см. ниже) через **Retrofit**. Эндпоинты
   `auth/registration`, `auth/login`, `auth/refresh`, `auth/check`, `auth/recovery`.
   Сетевого слоя в проекте ещё нет — добавляется в T-49.
2. **Полный гейт, 3 экрана:** `Онбординг → Авторизация → Мои списки`. На старте `GET auth/check`:
   токен валиден → сразу «Списки», иначе → «Вход».
3. **Хранение токенов** — в существующем `PreferencesService` (SharedPreferences +
   kotlinx.serialization): `accessToken`, `refreshToken`, `userId`. Без Room.
4. **Сложность пароля** — кроме «> 6 символов», оценка надёжности (слабый/средний/надёжный) и
   **анимированный индикатор** на экране регистрации (T-53/T-56).
5. **Безопасность при выходе** — данные привязаны к `userId`. Логаут **не удаляет** данные, но
   они перестают показываться (фильтр запросов по текущему пользователю); после повторного входа
   снова видны (T-58/T-59).

## Поток навигации

```
Онбординг ──▶ Вход ──▶ Мои списки
              ├──▶ Регистрация ──▶ Мои списки
              └──▶ Восстановление пароля
старт приложения: auth/check → (валиден) Мои списки | (нет) Вход
выход из аккаунта: очистка сессии → Вход (данные пользователя скрыты до повторного входа)
```

## API
## Регистрация POST auth/registration

| Поле     | Тип    | Описание       |
|----------|--------|----------------|
| email    | String | Почтовый адрес |
| password | String | Пароль         |

Тело запроса

```json
{
   "email": "test@gmail.com",
   "password": "1234567"
}
```

| Поле          | Тип    | Описание                                 |
|---------------|--------|------------------------------------------|
| access_token  | String | Токен для доступа к запросам             |
| refresh_token | String | Токен для запроса обновления accessToken |
| user_id       | Long   | Уникальный идентификатор пользователя    |

Тело при успешном ответе

```json
{
   "access_token": "qbAwrHtAbV1Ec9UA4xbFRzH7SiYIlHekPU3wRbJEAyxak4lk1",
   "refresh_token": "k77V6bTYlAiXNRejTbEkyKfvPeQoyL75ifOpfb5vG4AHSA8Yl",
   "user_id": 1
}
```

Возможные коды ответов:

- 201 Created
- 409 Пользователь уже существует
- 400 Некорректный email
- 400 Пароль менее 7 символов

## Проверка валидности токена GET auth/check

Header "Authorization" "Bearer qbAwrHtAbV1Ec9UA4xbFRzH7SiYIlHekPU3wRbJEAyxak4lk1"

| Header        | Тип    | Описание                                 |
|---------------|--------|------------------------------------------|
| Authorization | String | Токен для доступа к запросам             |

Тело при успешном ответе
| Поле          | Тип    | Описание                                 |
|---------------|--------|------------------------------------------|
| is_valid      | bool   | true - если токен еще работает           |

```json
{
   "is_valid": "true"
}
```
