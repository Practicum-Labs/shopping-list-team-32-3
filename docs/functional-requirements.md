## 1. Введение

### 1.1 Назначение приложения
Мобильное Android-приложение для ведения списков покупок. Пользователь создаёт
несколько списков (например, «Продукты», «Для дома», «Подарки к Новому году»),
наполняет их товарами с указанием количества и единицы измерения, отмечает
купленное и управляет списками (переименование, удаление, дублирование, сортировка).

### 1.2 Цель документа
Зафиксировать функциональные и нефункциональные требования так, чтобы команда
могла вести разработку, а заказчик — принимать результат по понятным критериям.

### 1.3 Область применения
Документ покрывает клиентское Android-приложение. Все данные хранятся локально в БД.
Серверная синхронизация в объём текущей версии **не** входит (см. §6, решение по сети).

## 2. Глоссарий

| Термин | Определение |

## 4. Функциональные требования

Формат каждого требования: **ID**, user story, критерии приёмки, приоритет
(**Обязательное** / **Опционально**). Под «диалогом» в критериях понимается модальная
шторка (bottom sheet) — см. [design.md](design.md).

### 4.1 Онбординг

#### FR-ONB-01 — Приветственный экран · *Опционально*
**Как** новый пользователь, **я хочу** при первом запуске увидеть краткое приветствие,
**чтобы** понять, что умеет приложение.
**Критерии приёмки:**
- При **первом** запуске показывается экран с иллюстрацией, логотипом, заголовком
  «Добро пожаловать в Список покупок!» и текстом «Создавайте списки, добавляйте товары,
  отмечайте, что уже куплено».
- Кнопка перехода открывает экран «Мои списки».
- При последующих запусках онбординг не показывается (факт прохождения сохраняется).

### 4.2 Главный экран «Мои списки»

#### FR-MAIN-01 — Создание нового списка · *Обязательное*
**Как** пользователь, **я хочу** создать новый список покупок, **чтобы** начать
собирать в него товары.
**Критерии приёмки:**
- На главном экране есть точка входа в создание списка (FAB).
- Открывается шторка «Добавление списка» с полем «Название списка» (placeholder
  «Новый список») и кнопками «Отмена» / «Создать».
- По «Создать» список с введённым именем сохраняется в БД и появляется в перечне.
- Пустое имя не позволяет создать список (кнопка неактивна или показывается ошибка).

#### FR-MAIN-02 — Отображение всех списков · *Обязательное*
**Как** пользователь, **я хочу** видеть все созданные списки, **чтобы** быстро
открыть нужный.
**Критерии приёмки:**
- Экран «Мои списки» показывает все сохранённые списки.
- Список сохраняется между запусками (данные из БД).
- Тап по элементу открывает экран редактирования этого списка.

#### FR-MAIN-03 — Переименование и удаление списка · *Обязательное*
**Как** пользователь, **я хочу** переименовать или удалить список, **чтобы**
поддерживать порядок.
**Критерии приёмки:**
- Доступны действия «Переименовать» и «Удалить» для каждого списка.
- Переименование открывает шторку с текущим именем в поле и кнопкой «Переименовать».
- Изменения сохраняются в БД и отражаются в перечне.

#### FR-MAIN-04 — Подтверждение удаления списка · *Обязательное*
**Как** пользователь, **я хочу** видеть подтверждение перед удалением, **чтобы**
не потерять список случайно.
**Критерии приёмки:**
- При удалении показывается подтверждение (шторка) с кнопками «Отмена» / «Удалить».
- «Отмена» оставляет список без изменений; «Удалить» удаляет его из БД.

#### FR-MAIN-05 — Свайп для переименования/удаления списка · *Опционально*
**Как** пользователь, **я хочу** вызывать действия свайпом элемента, **чтобы**
действовать быстрее.
**Критерии приёмки:**
- Горизонтальный свайп элемента списка открывает действия переименования/удаления.
- Удаление через свайп так же требует подтверждения (см. FR-MAIN-04).

#### FR-MAIN-06 — Дублирование списка · *Опционально*
**Как** пользователь, **я хочу** дублировать существующий список, **чтобы** не
создавать похожий с нуля.
**Критерии приёмки:**
- Доступно действие «Дублировать» для списка.
- Создаётся копия со всеми товарами и сохраняется в БД (имя копии — производное от
  исходного, напр. «… (копия)»).
- В копии **все отметки «куплено» сняты** — товары переносятся как некупленные
  (дубликат используется как шаблон для новой закупки).

#### FR-MAIN-07 — Иконка списка · *Опционально*
**Как** пользователь, **я хочу** задавать списку иконку, **чтобы** быстрее различать
списки визуально.
**Критерии приёмки:**
- У списка есть иконка; она отображается на карточке рядом с названием.
- Доступно действие «Сменить иконку» — открывается шторка с сеткой иконок
  (набор Material Symbols: cake, celebration, child_care, medication и др.).
- Выбранная иконка сохраняется в БД и применяется к списку.

#### FR-MAIN-08 — Поиск по спискам · *Опционально*
**Как** пользователь, **я хочу** искать список по названию, **чтобы** быстро найти
нужный среди многих.
**Критерии приёмки:**
- В верхней панели есть иконка поиска; тап открывает поле ввода.
- Перечень фильтруется по совпадению с введённым текстом (по названию).
- При отсутствии совпадений показывается состояние «ничего не найдено».

#### FR-MAIN-09 — Удаление всех списков · *Опционально*
**Как** пользователь, **я хочу** удалить все списки разом, **чтобы** быстро очистить
приложение.
**Критерии приёмки:**
- Доступно действие массового удаления списков.
- Перед удалением показывается подтверждение.
- По подтверждению все списки удаляются из БД.

### 4.3 Экран редактирования / создания списка

#### FR-LIST-01 — Добавление товара · *Обязательное*
**Как** пользователь, **я хочу** добавить товар с количеством и единицей измерения,
**чтобы** точно знать, что купить.
**Критерии приёмки:**
- Есть поле «Товар» (имя обязательно) и опциональные «Количество» и «Единицы».
- Единицы выбираются из набора: **л, мл, уп, пач, шт, кг, г**.
- Товар сохраняется в БД и появляется в списке; количество/единицы показываются как
  вспомогательный текст (напр. «1 л», «10 шт»).

#### FR-LIST-02 — Редактирование и удаление товара · *Обязательное*
**Как** пользователь, **я хочу** изменить или удалить товар, **чтобы** держать
список актуальным.
**Критерии приёмки:**
- Можно открыть товар на редактирование (имя, количество, единицы) и сохранить.
- Можно удалить товар; изменения сохраняются в БД.

#### FR-LIST-03 — Отметка товара как купленного · *Обязательное*
**Как** пользователь, **я хочу** отмечать купленные товары, **чтобы** видеть, что
ещё осталось.
**Критерии приёмки:**
- У товара есть чекбокс; отметка переключает состояние «куплено».
- Купленный товар отображается зачёркнутым; состояние сохраняется в БД.

#### FR-LIST-04 — Контекстное меню списка · *Обязательное*
**Как** пользователь, **я хочу** меню действий над списком, **чтобы** управлять им
целиком.
**Критерии приёмки:**
- В меню доступны: «Переименовать», «Удалить», «Очистить купленные».
- «Очистить купленные» удаляет из списка все товары с отметкой «куплено».
- Действия сохраняются в БД.

#### FR-LIST-05 — Сортировка по алфавиту · *Обязательное*
**Как** пользователь, **я хочу** сортировать товары по алфавиту, **чтобы** быстрее
ориентироваться.
**Критерии приёмки:**
- Доступна сортировка товаров по алфавиту (через меню «Сортировка»).
- Выбранный режим сортировки применяется к отображению списка.

#### FR-LIST-06 — Свайп для редактирования/удаления товара · *Опционально*
**Как** пользователь, **я хочу** вызывать действия над товаром свайпом, **чтобы**
действовать быстрее.
**Критерии приёмки:**
- Горизонтальный свайп элемента товара открывает редактирование/удаление.

#### FR-LIST-07 — Автоподсказки имени товара · *Опционально*
**Как** пользователь, **я хочу** видеть подсказки по ранее введённым товарам,
**чтобы** не печатать имя целиком.
**Критерии приёмки:**
- При добавлении товара его имя сохраняется в отдельной таблице БД (шаблоны имён).
- При следующем вводе показываются всплывающие подсказки по совпадению (напр. ввод
  «Мол» → «Кокосовое молоко», «Молоко», «Соевое молоко», «Сухое молоко»).
- Тап по подсказке подставляет имя товара в поле.

#### FR-LIST-08 — Ручная сортировка drag-and-drop · *Опционально*
**Как** пользователь, **я хочу** вручную перетаскивать товары, **чтобы** задать
свой порядок.
**Критерии приёмки:**
- Режим «Пользовательская» сортировка позволяет перетаскивать товары (drag handle).
- Заданный порядок сохраняется в БД и восстанавливается при открытии списка.

#### FR-LIST-09 — Удаление всех товаров · *Опционально*
**Как** пользователь, **я хочу** удалить все товары списка разом, **чтобы** начать
список заново.
**Критерии приёмки:**
- В контекстном меню доступно действие «Удалить все» (товары).
- Перед удалением показывается подтверждение.
- По подтверждению все товары списка удаляются из БД (сам список сохраняется).

## 5. Нефункциональные требования к работе приложения (NFR)

> Технические/инфраструктурные NFR вынесены в [architecture.md](architecture.md):
> NFR-02 (detekt) — § «Статический анализ»; NFR-07 (релизная сборка) — § «Релизная
> сборка и подпись». NFR-01 (темизация) описан в [design.md](design.md).

### NFR-03 — Смена ориентации экрана · *Опционально*
Все экраны поддерживают портретную и альбомную ориентацию без потери данных и состояния.
Состояние UI (включая открытые шторки и введённые данные) хранится в MVI `State` и
переживает смену конфигурации (см. [architecture.md](architecture.md) § «Строительные
блоки MVI»).

### NFR-04 — Маленькие экраны · *Опционально*
Корректное отображение на устройствах класса Small phone (без обрезания контента и
наложений; элементы доступны через прокрутку).

### NFR-05 — Отдельная вёрстка для планшетов · *Опционально*
На планшетах доступен режим, где списки покупок и редактирование выбранного списка
видны и доступны для правки **на одном экране** (master-detail). «Мои списки» и
«Редактирование списка» отображаются одновременно.

### NFR-06 — Стабильность · *Обязательное*
Отсутствие runtime exception при штатных пользовательских сценариях.

> Связанные NFR (для полноты): **NFR-01** — светлая/тёмная темы (опц., см.
> [design.md](design.md)); **NFR-02** — detekt (опц.); **NFR-07** — релизная сборка
> и подпись (обязательное) — оба в [architecture.md](architecture.md).

## 6. Принятые решения

| # | Вопрос | Решение |
|---|---|---|
| 1 | Набор единиц измерения | Используем набор из Figma: **л, мл, уп, пач, шт, кг, г**. |
| 2 | Валидация пустых имён | Запрещаем сохранять пустое имя списка и пустое имя товара (кнопка сохранения неактивна / показывается ошибка). |
| 3 | Пустой список | Список можно создать без товаров; пустой список отображается с подсказкой добавить первый товар. |
| 4 | Сеть / Retrofit | В текущей версии сеть не используется. Retrofit подключаем только если появятся реальные запросы. |
| 5 | Реализация диалогов | Все диалоги/меню реализуются как модальные шторки (bottom sheet) со scrim. |

## 7. Карта экранов и навигация

```
[Онбординг] ─(первый запуск)─▶ [Мои списки]
                                    │
[Мои списки] ──(FAB)──────────────▶ Шторка «Добавление списка»
     │  ├─(переименовать)─────────▶ Шторка «Переименование списка»
     │  ├─(удалить)───────────────▶ Подтверждение удаления (шторка)
     │  ├─(дублировать)──────────▶ копия в перечне
     │  ├─(сменить иконку)───────▶ Шторка выбора иконки
     │  ├─(поиск)────────────────▶ Режим поиска (найдено / не найдено)
     │  └─(удалить все)──────────▶ Подтверждение (шторка)
     │
     └─(тап по списку)───────────▶ [Редактирование списка]
                                        ├─ добавить/изменить товар (форма товара)
                                        │       └─ автоподсказки имени
                                        ├─ отметить куплено (зачёркивание)
                                        └─ контекстное меню:
                                            Сортировка (По алфавиту / Пользовательская),
                                            Удалить все, Очистить купленные
```

Подробное описание экранов и состояний — в [design.md](design.md).
На планшетах (NFR-05) «Мои списки» и «Редактирование списка» отображаются
одновременно (master-detail) на одном экране.

## 8. Сводный чек-лист требований

**Онбординг:** приветственный экран при первом запуске (опц.).

**Главный экран:** создание списка · просмотр всех списков · переименование/удаление ·
подтверждение удаления · свайп-действия (опц.) · дублирование (опц.) · иконка списка (опц.) ·
поиск по спискам (опц.) · удаление всех списков (опц.).

**Редактирование списка:** добавление товара (кол-во + единицы) · редактирование/удаление ·
отметка «куплено» · контекстное меню (переименовать/удалить/очистить купленные) ·
сортировка по алфавиту · свайп-действия (опц.) · автоподсказки имён (опц.) ·
drag-and-drop сортировка (опц.) · удаление всех товаров (опц.).

**NFR:** темы (опц., [design.md](design.md)) · detekt (опц., [architecture.md](architecture.md)) ·
смена ориентации (опц.) · маленькие экраны (опц.) · планшеты (опц.) · отсутствие runtime
exception · релизная сборка + подпись ([architecture.md](architecture.md)).
